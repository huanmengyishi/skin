# v1.2 当前生成链审计（Vision → Evidence → Spec）

> 依据：当前源码（src/generator/vision.ts、src/core/spec.ts、src/generator/iterate.ts）与 run-010/run-011 真实证据。

## 10 问

1. **当前 Vision 原始结果是什么？** vision-http（ovh/Qwen2.5-VL-72B-Instruct）返回的自由文本；可能是指令要求的 JSON，也可能是任意其它 JSON 结构或散文。原样存 vision-raw.json。
2. **当前 VisionEvidence 是什么？** {summary, layout[{region,content}], entities[], colors[{hex,share}], text, raw?, source?{kind,provider,model}, colorSource?}。colors 为空时由本地确定性量化兜底（colorSource=local-quantization）。
3. **toEvidence 做什么？** 唯一归一化闸门：extractJson → 字段归一 → 非法 hex 颜色丢弃（不伪造）→ summary 空时散文前 500 字兜底。
4. **哪些字段来自 Vision？** summary/layout/entities/colors/text（观察事实；colors 可能是本地量化）。
5. **哪些字段来自 DeepSeek？** SkinDesignSpec 全部字段（visualStyle/colorPalette/typography/spacing/9 个 CSS 字段/chrome/decorative/assetCandidates/customCss）。
6. **哪些字段仍然混合？** colorPalette：模型从 evidence.colors 选色或自行新造（无一致性检查）；layout/entities 未被要求与 Spec 对齐；CSS 字段全为模型设计（合理，但无 provenance 标注）。
7. **当前 SkinDesignSpec schema？** src/core/spec.ts：visualStyle/colorPalette[{hex,role,share}]/typography{family,mono}/spacing{density,radius}/9 CSS 字符串/chromeElements/decorativeElements/assetCandidates/customCss?。
8. **哪些字段有 provenance？** 只有 evidence 级 colorSource/source；Spec 字段无逐字段来源。
9. **哪些字段没有 provenance？** 全部 Spec 字段（含 colorPalette 的取色来源）。
10. **失败域怎么分类？** VISION/EVIDENCE_NORMALIZATION/SPEC/CODEGEN/CODEGEN_OUTPUT/RENDER/REPOSITORY/UNKNOWN（GenerationResult.failureDomain + failureClass）。v1.2 需拆分 SPEC→SPEC_VALIDATION、增 PROVENANCE/EVIDENCE_VALIDATION。

## v1.2 决策（依据本审计）

- VisionEvidence 保持现有字段（Q2 已稳定验证），新增 meta（imageKey/provider/model/analysisVersion/at）与 regions 别名：layout 即模型区域观察（vision_ground/crop 属 agent 工具 seam，宿主生成器不可调用——边界记录在案，v1.4 再研究）。
- 新增 SpecProvenance：逐字段来源（vision/local-quantization/model-design/fallback）+ evidenceRef + interpretation（DeepSeek 的显式设计解释，供 system 提示要求输出）。
- 新增 Evidence Consistency（校验第三层）：兼容性判定（不要求相等；全色偏离超阈值 → WARN 记录，不 REJECT；非法 hex 仍 REJECT——策略文档化）。
- DeepSeek 输入结构化强化：颜色必须取自 evidence.colors（角色分配是设计），不得新造；输出要求附 interpretation 数组（不进 Spec 公共契约，仅 provenance）。
- DeepSeek 输出架构不变：raw → extractJson（安全解析）→ validateSkinDesignSpec → reject/normalize（Q1/Q2 实证模型不可靠，此架构已纳入现实）。
- 缓存不变（v2 键）；缓存命中后 provenance 重建（不随缓存丢失）。
