# v1.4 Render → Diff → Repair 架构审计

> 对象：当前源码（src/generator/iterate.ts、fidelity.ts、diff.ts、screenshot.ts、render.ts、vision.ts、package-build.ts、downscale.ts、vision-queue.ts）。调查性质：先回答 18 问，再给系统图与决策。

## 一、18 问（以当前源码为准）

1. **当前如何从 SkinPackage 启动真实 Harness 渲染？**
   iterate.ts 每迭代：buildSkinPackage（v1.3）→ buildPreviewHtml（render.ts：把包的真实 tokens/theme.css/client/index.js 内联进自包含 HTML，含 data-slot 的 Harness 壳 mock：sidebar/conversation/shell.overlay/输入按钮）→ screenshotHtml（puppeteer-core + Edge/Chrome 发现，1200×720）。边界：**真实包内容 + 真实浏览器 + 固定壳 mock**（宿主完整 shell 无法按包无头渲染——自 v1.0.0 即确立的渲染边界，如实记录，不冒充真实宿主 UI）。

2. **当前如何得到 screenshot？**
   screenshotHtml：file:// 打开 preview.html → 双 rAF → page.screenshot(PNG) → 返回渲染样式指纹（body bg/font/sidebar/overlay 计算样式 JSON）。

3. **screenshot 是否与参考图拥有统一裁剪/缩放坐标系？**
   是：截图 viewport 固定 1200×720；参考图经 renderImageToPng 以 object-fit:cover + 居中裁剪归一为 1200×720 PNG。两者等尺寸，全部像素/区域指标在同一坐标系（Q1 已验收）。v1.4 不重造 crop 规则。

4. **Q1 fidelity 当前如何计算？**
   fidelity.ts computeFidelityReport：palette（4-bit 量化直方图交集 + 主导色最近距离）、layout（4×4 灰度余弦）、region（8×8 平均通道差 + 最差格）、pixel（diffRatio 阈值 16）、structure（非空白方差）。主指标=Reference Fidelity；辅=Iteration Stability（轮间 diffRatio + 指纹）；前置=Runtime Correctness。

5. **当前是否能输出最差区域？**
   半成品：diff.ts 输出 8×8 最差 5 格（ratio 排序）；regionMeanDelta 输出单个最差格。但没有 id/页面区域映射/指标归属/候选字段/裁剪件，也没有落盘 worst-regions.json。

6. **最差区域如何映射回页面区域？**
   无显式映射。壳 mock 几何是固定的（sidebar 宽 220px、overlay 右上 280px、conversation 其余）→ 可建立 cell→页面区域映射表（v1.4 新增）。

7. **Vision Router 当前能否重新观察局部区域？**
   经 brain seam 只能整图观察（analyzeImage）。vision_ground/crop 是 agent 工具 seam，宿主生成器进程内不可调用（v1.2 已记录边界）。

8. **vision_ground/crop 是否能通过 agent seam 调用？**
   否。v1.4 最小方案（§22 许可）：**reference.png（1200×720 归一坐标系）按 bbox 裁剪（pngjs）+ 最近邻放大 3× → analyzeImage 二次观察**；限制如实记录为 Agent Seam limitation，不复制 vision-router 内部实现。

9. **当前 DeepSeek 输入如何构造？**
   designSpec：JSON.stringify({evidence, hints})（v1.2 证据纪律系统提示词）；repair（旧）：JSON.stringify({currentSpec, diff, evidence, instruction})，输出=完整新 spec（全量重写形态，无结构化决策/无 patch 语义）。

10. **当前 DesignSpec 哪些字段可以被 patch？**
    旧 repair 返回整个 spec——无 patch 概念。可 patch 面（v1.4 定义）= SkinDesignSpec 设计字段：colorPalette[*].{hex,role,share}、typography.{family,mono}、spacing.{density,radius}、9 个 CSS 片段字段 + shapeLanguage、customCss、visualStyle、chromeElements/decorativeElements/assetCandidates。受保护：provenance（编排层产物）、一切包/仓库/运行时元数据。

11. **Package 如何重新构建？**
    v1.3 buildSkinPackage（同一 BuildConfig）→ validateBuiltPackage；iterate 最终门 sealPackage → repository.install/replace。v1.4 每轮 Repair 后走同一条路。

12. **Build 是否仍然 deterministic？**
    是（run-013 验收：同 Spec+Config 跨目录跨进程 byte-identical）。v1.4 只在循环里重复调用同一 builder，不改 builder。

13. **当前生成循环如何保存 iteration state？**
    generation/<runId>/：input.png、analysis.json、evidence.json、colors.json、provenance.json、validation.json、design-spec.json、iteration-N/{skin/,preview.html,screenshot.png,fidelity.json}、repair-prompt-N.txt、final/、report.json。缺：worst-regions、region-evidence、repair-decision、spec-patch、metric-delta、render 元数据。

14. **当前是否已经有 maxIterations？**
    有：maxIterations 默认 3（1..8 钳制）——但语义是"总渲染轮数"（iteration-0..N-1），旧 repair 每轮全量重写。

15. **当前如何判断收敛？**
    轮间：diffRatio ≤ 0.02 且指纹不变（Iteration Stability）。不与 Q1 主指标联动，无 no-repair 收敛、无改善/退化判定。

16. **当前如何防止 repair oscillation？**
    无。旧 repair 由 fixture 交替颜色制造可见差异，真实链无防振荡机制。

17. **当前如何防止某一轮改善一个指标却恶化另一个指标？**
    无显式保护。fidelityNotWorse 只用于 interpretation.improved 提示，不参与循环控制。

18. **当前 failure domain 如何记录？**
    FailureDomain 联合类型：VISION/EVIDENCE_NORMALIZATION/EVIDENCE_VALIDATION/SPEC/SPEC_VALIDATION/PROVENANCE/CODEGEN/CODEGEN_OUTPUT/CSS_VALIDATION/MANIFEST_BUILD/ASSET_BUILD/PACKAGE_BUILD/PACKAGE_VALIDATION/INTEGRITY/RENDER/REPOSITORY/UNKNOWN。缺：FIDELITY/REGION_DIAGNOSIS/VISION_RECHECK/REPAIR_DECISION/SPEC_PATCH。

## 二、v1.4 目标系统图

```text
iteration-N:
  1 build (v1.3 builder) + validateBuiltPackage → packageHash
  2 render：buildPreviewHtml（真实包内容 + 壳 mock）→ screenshotHtml（真实浏览器 1200×720）→ RenderResult
  3 fidelity（Q1 evaluator 原样复用）→ fidelity.json
  4 diagnose：buildWorstRegions（8×8 最差格 + 页面区域映射 + 候选 Spec 字段）→ worst-regions.json
  5 no-repair gate：五维阈值全满足 → CONVERGED（不调模型）→ 停止
  6 re-observe：top worst region → reference.png bbox 裁剪（pngjs）+3× 放大 → analyzeImage（VisionQueue 内）
     → RegionEvidence（toEvidence 归一化；429 → VISION_RECHECK，安全停止，上一轮包保持）
  7 repair decision：DeepSeek → RepairDecision JSON → validateRepairDecision（白名单/类型/expectedEffect/预算）
     → 非法时单次重问（maxRepairAttempts=2，记录）；仍非法 → REPAIR_DECISION 安全停止
  8 spec patch：applySpecPatch（结构化、深拷贝）→ validateSkinDesignSpec → 振荡检测（seenSpecHash）
  9 rebuild（同一 v1.3 builder）→ re-render → re-fidelity → metricDelta → 状态判定：
     IMPROVED（有意义改善且未收敛）→ 继续
     CONVERGED（改善 + 轮间稳定 + 指纹不变）
     UNCHANGED（无有意义改善）→ NO_IMPROVEMENT 停止
     REGRESSED（任一副作用退化）→ 停止，最终包=上一轮
     OSCILLATION（spec 状态重现）→ 停止
     MAX_ITERATIONS（预算耗尽）
 10 最终：最佳（最后非退化）包 → seal → repository.install/replace（既有管线）
```

## 三、v1.4 决策清单

- D1 新建 src/generator/diagnosis.ts：WorstRegion 升级（id/bbox/metric/score/rank/pageRegion/likelyIssueDomain/candidateSpecFields/裁剪件）、SPEC_RESPONSIBILITY_MAP（页面区域→候选字段）、metricDelta、cropPng。
- D2 新建 src/generator/repair.ts：RepairDecision schema + validateRepairDecision（设计字段白名单、类型/值域校验、__proto__/路径穿越阻断、targetRegion 存在性、reason/expectedEffect 必填、maxChangedFieldsPerIteration 预算）+ applySpecPatch + 振荡检测。
- D3 iterate.ts 循环重写：状态机 IMPROVED/UNCHANGED/REGRESSED/CONVERGED/OSCILLATION/MAX_ITERATIONS/FAILED；no-repair gate；每轮工件（render.json/worst-regions.json/region-evidence.json/repair-decision.json/spec-patch.json/metric-delta.json）；失败域 +FIDELITY/REGION_DIAGNOSIS/VISION_RECHECK/REPAIR_DECISION/SPEC_PATCH。
- D4 GeneratorBrain 面变更：repair() → repairDecision(RepairInput)；新增 reobserveRegion(cropPath, regionId)。liveBrain/fixtureBrain 同步实现；旧 repair 移除（生成器内部面，未冻结）。
- D5 渲染抽象：RenderResult{viewport,crop,environment,packageHash,runtimeStatus,warnings,artifacts}——记录层，不改 screenshotHtml 行为。
- D6 平台边界不变：puppeteer-core + Edge/Chrome 发现继续；vision_html_screenshot 不作为唯一实现；不 import vision-router 内部。
- D7 429 规则不变：vision-router 拥有 retry；dsh-skin 只有 queue/cache/downscale/分类；二次观察 429 → VISION_RECHECK，保留上一轮包。
- D8 v1.3 builder 原样复用（每轮 Spec Patch → buildSkinPackage → validateBuiltPackage）；禁止 Repair 直改 theme.css。
- D9 壳 mock 页面区域几何固定（sidebar 220px / overlay 右上 280px / conversation 其余），cell→区域映射表写入 docs/v1.4-repair-policy.md 附录；映射仅作候选提示，最终修改决策归 DeepSeek。
