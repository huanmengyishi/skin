# v1.3 确定性构建规范（Deterministic Package Build）

> 理想语义：Package = build(SkinDesignSpec, BuildConfig)。同一 (Spec, BuildConfig) ⇒ 同一 Package 字节。

## 1. 输入身份（Input Identity）

| 身份 | 定义 | 说明 |
| --- | --- | --- |
| Spec Identity | buildSkinPackage 收到的完整 spec 对象（含 provenance，如有）经 JSON.stringify 后 sha256 | 规格变化 ⇒ 身份变化 ⇒ 包可能变化 |
| Build Configuration | BuildConfig 全字段 JSON sha256（packageVersion/generatorVersion/previewMode/assets 路径与字节/evidence 摘要） | 配置变化 ⇒ 身份变化 |
| Generator Version | 代码内常量 PACKAGE_BUILDER_VERSION（dsh-skin@1.3.0） | 实现变化 ⇒ 产物可能变化；入 build-manifest |
| Package Version | BuildConfig.packageVersion（semver；缺省常量 '0.1.0'） | 禁止时间戳/随机版本；来源=用户或稳定常量 |
| Asset Set | BuildConfig.assets（包内相对路径→字节），逐字节复制 | 与 Vision Cache / 图片哈希无关 |

规则：build key（若建 Build Cache）= sha256(specIdentity + buildConfigIdentity + generatorVersion)；**禁止用 image hash 作为包构建唯一键**（Vision Cache 与 Build Cache 分离，本阶段不引入 Build Cache，规则先立）。

## 2. 输出规范化（Output Normalization）

- 文件集合：manifest.json、theme/light.json、theme/dark.json、styles/theme.css、client/index.js、preview/light.svg、preview/dark.svg、（assets/*）、（seal 后 integrity.json）；buildManifest.files 按包内相对路径排序（localeCompare）。
- JSON：JSON.stringify(..., null, 2) + 换行；键序=构造序（固定）。
- CSS：css-render 固定块序（基础→侧栏→会话区→浮层→输入→按钮→代码→图标→customCss），声明按 parse 顺序首胜去重；两空格缩进；块间空行；结尾换行。
- client：固定模板字符串（id 来自 naming，无 bundle hash、无时间戳）。
- preview svg：固定模板 + 角色色。
- 路径：**仅包内相对路径**（preview/light.svg、styles/theme.css…）；禁止绝对路径/盘符/UNC/file:// 进入任何包内文件（校验器扫描）。
- 时间戳：包内文件一律无时间戳；时间只存在于 generation 工作区工件与 registry.updatedAtMs（目录 mtime，非包内容）。
- 随机性：buildSkinPackage 无任何 random/uuid/nonce；id 来自命名（slugify，确定性）；staging 临时名仅限仓库安装层。

## 3. 内容确定性 vs 文件路径确定性

- 内容确定性（本阶段验收）：同 (Spec, Config) 在任何目录/进程构建 ⇒ 全部文件字节一致（A/B + 跨目录 + 跨进程三重验收）。
- 文件路径确定性：包内引用全部相对路径；staging/工作区绝对路径永不进入包文件（校验器 + 单测断言）。

## 4. 已知的非确定性边界（显式声明，不得写「可接受差异」）

| 产物 | 归属 | 非确定性原因 | 处理 |
| --- | --- | --- | --- |
| iteration-N/screenshot.png、preview.html | generation 工作区 | 浏览器渲染器/编码元数据 | 不进 Package；确定性对象不含截图 |
| 导出 zip（repository/export.ts） | 导出层（v1.6 workshop 面） | fflate zipSync 嵌入生成时间 | 不在 v1.3 build 范围；workshop 阶段建 deterministic zip policy（SOURCE_DATE_EPOCH 或固定 mtime） |
| runId / evidence.meta.at / registry.updatedAtMs | 工作区/注册表元数据 | 时间戳 | 非包内容，契约允许 |

## 5. 版本策略

- packageVersion 来源优先级：用户（GenerateInput.version）> 稳定常量 '0.1.0'。禁止 1.0.<timestamp>。
- 版本必须过 semver 校验（manifest 校验器 + builder 前置校验 MANIFEST_BUILD 域）。

## 6. 失败域（v1.3 拆分）

SPEC / SPEC_VALIDATION（输入层）→ MANIFEST_BUILD（命名/版本/preview 策略）→ ASSET_BUILD（资产路径/复制）→ PACKAGE_BUILD（IO/原子落位）→ CSS_VALIDATION（css-render 结构问题/样式表语法）→ PACKAGE_VALIDATION（产物校验器）→ INTEGRITY（hash/写 integrity.json）→ REPOSITORY（安装）。CODEGEN/CODEGEN_OUTPUT 保留兼容。

## 7. 验收断言（不可协商）

1. 同 Spec+Config 双构建：manifest/theme/styles/client/preview（+seal 后 integrity）全文件 **byte-identical**（不比较 zip）。
2. 跨目录（不同 staging 路径）+ 跨进程（独立 node 进程）各复验一次。
3. 同图不同 Spec（run-012 的 2.jpg 两轮）⇒ 包内容**必须不同**（证明确定性由输入决定，与图片来源无关）。
4. seal 两次 ⇒ integrity.json 字节一致；改动任一文件 ⇒ verifyPackage 失败。
5. 校验器拒绝：坏 manifest、坏 CSS（花括号失衡/引号外 CJK）、缺 client、preview 路径缺失、可执行文件、远程 URL、绝对路径、symlink。
