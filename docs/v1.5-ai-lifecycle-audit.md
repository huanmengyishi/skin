# v1.5 AI Skin Lifecycle 架构审计

> 对象：当前源码（src/generator/iterate.ts、src/repository/*、src/client/controller/controller.ts、src/client/ui/skin-card.tsx、src/index.ts 路由、src/client/index.ts）。调查性质：先回答 20 问，再给实体边界与决策。

## 一、20 问（以当前源码为准）

1. **Generation Workspace 如何组织？**
   $DSH_HOME/skins/cache/generation/<runId>/（runId=gen-<ISO>-<rand6>）：input.png、vision-raw/evidence/colors/provenance/validation/design-spec、iteration-N/{skin,preview.html,screenshot,fidelity,worst-regions,region-evidence,repair-decision,spec-patch,metric-delta,render}.json、final/、report.json、build-{config,manifest}.json。无统一索引——历史只能靠扫目录 + report.json。

2. **一次生成的唯一标识是什么？**
   runId（gen-<ISO ts>-<rand6>）。生成时间与随机数构成——只用于工作区命名（非包内容，v1.3 已验收）。

3. **当前 SkinPackage 如何与 generation 关联？**
   隐式：installed 包（source=generated，包目录=final 构建）与 run 目录无记录关联；/api/regenerate 靠扫描 report.json 找 skinId 最新 run。

4. **Repository 是否已有 generated 来源？** 是：install(finalDir,{kind:'generated'}) → skins/generated/<id>；discover/registry/分辨率策略全部已支持。

5. **generated 与 installed 的关系？** 来源根不同；同 id 时 installed>generated 遮蔽（ResolutionPolicy 冻结）。AI 生成落 generated 根。

6. **生成历史目前保存在哪里？** run 目录 + report.json；无索引、无父子链、无失败域记录面。regenerate 通过扫描关联。

7. **AI Skin 是否需要独立 lifecycle record？** 需要最小 record（生成过程元数据），但 Skin 身份不重复造：skinId 仍是唯一身份；AISkin 列表 = 生成记录按 skinId 投影 + registry 状态 join（派生，不建第二身份存储）。

8. **重新生成应该覆盖原 Skin 还是产生新版本？** 同一 skinId + patch++ 版本 + 新 generationId（parent=上一代）。Repository.replace 已有原子回滚语义，直接复用。

9. **编辑 metadata 是否需要重新构建 Package？** 否。既有 /api/skins/:id/meta 已走 manifest 写入 + integrity 重算（hashPackage）+ registry 刷新——不调用 Vision/DeepSeek；保持。

10. **编辑 DesignSpec 是否应该生成新版本？** 是：Spec Patch（复用 v1.4 repair.ts 校验/patch）→ 新 generation → v1.3 确定性构建 + v1.4 修复环 → replace → 版本+1。

11. **删除 AI Skin 是否删除 generation history？** 否：uninstall 只走 repository.remove（包），generation workspace 与记录保留（供 reinstall/regenerate/export）。历史不自动回装。

12. **导出 Package 如何实现？** 既有 /api/skins/:id/export（fflate zip，包目录=纯契约文件）。v1.5 补 EXPORT 失败域标注；不做第二套导出。

13. **Skin Center 是否已有 generated skin 展示能力？** 是：gallery 列出全部来源（E2E-5 实证）；来源过滤按钮只覆盖 builtin/installed（generated 无专用过滤按钮——补）。

14. **Controller 是否具备 AI lifecycle operation？** 部分：generate/regenerate/saveMeta/exportUrl 已有；缺 createGeneration（两段式）/取消/状态查询/spec-edit/reinstall/历史列表。

15. **哪些数据必须持久化？** 生成记录索引（atomic）、run 工件（工作区）、repository 包（既有持久化）。

16. **哪些数据只应该存在 generation workspace？** vision-raw、evidence、provenance、iteration-N、screenshots、fidelity、repair-decision、logs——不得进 Package（v1.3 已锁）。

17. **如何关联 image → evidence → spec → package → installed Skin？** 记录字段链：inputHash（image sha16）→ evidenceHash → specHash → packageHash（build-manifest/tree sha）→ skinId+packageVersion；install 落 repository（既有管线）。

18. **崩溃/中断后 generation 如何恢复？** 启动对账：records 索引中 RUNNING 态记录 → FAILED + failureDomain=RECOVERY；run 目录仍在（工作区）；repository 不受影响（staging 清扫已有 F 门）。

19. **同一 Skin ID 的多次生成如何关联？** parentGenerationId 链 + 按 skinId 过滤的列表；版本=packageVersion（每代 patch++），generation 计数≠版本。

20. **什么数据属于 Skin identity / Generation identity？**
    Skin：skinId、manifest 字段、packageVersion、source/trust（仓库/安装策略）。
    Generation：generationId（runId）、parentGenerationId、inputHash/evidenceHash/specHash/packageHash、status/failureDomain、category、startedAt/completedAt、stage。

## 二、实体边界（v1.5 决策）

- GenerationState（QUEUED→ANALYZING→SPEC_GENERATED→BUILDING→RENDERING→REPAIRING→VALIDATING→COMPLETED | FAILED | CANCELLED）与 Skin state（Repository+Runtime 现状：ok/active/未安装）分离；不建第二 Runtime 状态机。
- AISkinRecord = 派生投影（records 按 skinId 聚合 + registry join），不新增 aiSkinId；category 属 Generation 元数据（manifest 冻结面不动）。
- 版本策略：create=0.1.0（常量，可输入覆盖）；regenerate/spec-edit=当前版 patch++（SemVer 语义不变）。
- 并发：同 skinId 单 active generation（keyed lock）；跨 skin 并发由 Q5 VisionQueue 串行化 provider。
- 取消：AbortSignal + 阶段检查点；CANCELLED ≠ 删除；上一版包不受影响（安装只发生在成功后）。
- 记录原子性：records.json 整体原子重写（复用 writeFileAtomic，与 registry 同机制）+ 每 run record.json。
- 恢复：启动扫描 RUNNING 记录 → FAILED/RECOVERY；孤儿 run 目录保持工作区（不进 repository）。
- UI：Skin Center 新增「AI 皮肤」面板（两段式创建：先 createGeneration 后 run + 轮询 /api/generations/:id；取消按钮；重新安装/设计编辑/历史状态/failureDomain 可读化）。UI 只经 SkinController + AIGenerationController（架构隔离测试锁定）。
