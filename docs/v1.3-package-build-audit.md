# v1.3 Package Build 架构审计（SkinDesignSpec → SkinPackage）

> 对象：当前源码（src/generator/codegen.ts / css-render.ts / iterate.ts、src/core/spec.ts / manifest.ts / integrity.ts、src/repository/repository.ts / security.ts）。调查性质，只回答事实，不改代码。
> 输出：20 问逐题回答 + 真实构建图 + v1.3 决策清单。

## 一、20 问（以当前源码为准）

1. **当前 SkinDesignSpec 从哪里进入 Package Builder？**
   src/generator/iterate.ts 的 generateSkin：每个迭代 `writeSkinPackage(env.fs, iteration-N/skin, spec, naming)`，最终门再 `writeSkinPackage(env.fs, final, last.spec, naming)`。入口单一，但 builder 不是独立契约面（无返回结果协议、无失败域）。

2. **Package Builder 有哪些输入？**
   spec + naming{id,name,author,description,tags} + destDir。**没有 BuildConfig**：版本写死、generatorVersion 无、preview 策略无、资产集无。

3. **哪些字段来自 Spec？**
   colorPalette→theme/{light,dark}.json（ROLE_TOKEN 角色映射 + 暗色 40% 压暗）；typography.family/mono→theme.css（基础块/pre、code 块 font-family）；spacing.radius→border-radius（基础/输入/按钮块）；shapeLanguage/backgroundStyle→基础块；headerStyle/sidebarStyle→侧栏块；cardStyle/messageStyle→会话区+浮层块；borderStyle/shadowStyle→浮层/输入/按钮块；inputStyle/buttonStyle→输入/按钮块；iconStyle→svg 块；customCss→顶层透传；bg/brand/label 角色色→preview svg。**未渲染字段（意图层）**：visualStyle、spacing.density、chromeElements、decorativeElements、assetCandidates（不产生任何包文件）。

4. **哪些字段由 Builder 自动生成？**
   manifest.preview（preview/light.svg、dark.svg）；client/index.js（no-op apply 模板）；preview svg 的布局模板；theme.css 的槽位选择器与骨架声明（border-radius/font-family）。

5. **哪些字段来自生成时间？**
   无。包内容（manifest/theme/styles/client/preview）不含任何时间戳。生成时间只出现在 generation 工作区工件（runId、evidence.json.meta.at、registry.updatedAtMs=目录 mtime）——均不进 Package。

6. **哪些字段来自随机数？**
   无。runId 的 Math.random 与仓库 staging 的 randomBytes 都只作用于工作区/暂存目录名，不进入包内容。

7. **哪些字段来自环境？**
   无。builder 不读 process.env / cwd / 网络 / 机器路径。

8. **哪些资源需要复制？**
   当前没有复制任何外部资源：assetCandidates 只是意图，不落地；input.png 不进包。**v1.3 补最小资产管道**：BuildConfig.assets（包内相对路径 → 字节）逐字节复制。

9. **哪些资源需要编译？**
   styles/theme.css（css-render 结构化渲染）；client/index.js（模板字符串）；preview/light|dark.svg（模板字符串）。三者均为确定性纯函数。

10. **preview 如何产生？**
    deterministic SVG（bg/brand/label 色 + 固定布局模板）。iteration-N/screenshot.png 是浏览器截图，**只进 generation 工作区**，不进 Package（preview 字节 = svg，稳定）。

11. **manifest 如何产生？**
    codegen.writeSkinPackage 内联构造：id/version/name/author/description/tags 来自 naming + 常量；skinApiVersion=SKIN_API_VERSION(1)；preview={light:'preview/light.svg',dark:'preview/dark.svg'}。**version 硬编码 '0.1.0'**（稳定但策略隐式，不可配）。

12. **integrity 如何产生？**
    Builder 不产。repository.install 在 staging 二次校验时：integrity.json 存在则 verifyPackage，缺失则 hashPackage 生成。hashPackage 遍历**排除 integrity.json 自身**（无自引用，官方既有方案）；路径排序（localeCompare），内容=sha256。generateSkin 最终门在安装前为 final 目录写 integrity.json。

13. **package version 如何决定？**
    硬编码常量 '0.1.0'。可复现，但来源不可配置、策略未文档化。

14. **build 是否 deterministic？**
    当前实现上是：JSON.stringify 键序=插入序（固定）、css-render 块序/声明序固定、svg/client 模板固定。但**没有 BuildConfig/输入身份/输出规范作为契约锁定**，也没有 A/B 字节级验收证据。

15. **当前哪些输出可能不稳定？**
    (a) ZIP 导出（repository/export.ts fflate zipSync）默认嵌入 zip 生成时间 → zip 字节跨时刻不稳定——导出不在 v1.3 build 范围，标注为 workshop 阶段专项；(b) 浏览器截图 PNG（编码器版本/时间元数据）——仅工作区，不进包；(c) manifest.version 常量虽稳定但无显式策略。

16. **当前 Package Validator 在哪里？**
    分散：repository.install 校验 manifest+安全门+完整性；discover 校验 manifest+完整性。**不存在**单一「构建产物校验器」：CSS 结构、client 形态、preview 存在性、绝对路径、资产清单在 install 前没有统一门（CSS 只有 iterate 里的字符串级 cssStylesheetIssues 检查）。

17. **当前 Repository install 依赖哪些字段？**
    manifest.json（validateManifest + isValidSkinId + 同 id 冲突检查）；security 扫描（可执行扩展名/远程 URL/symlink）；integrity.json（存在则验证，缺失则生成）。registry 依赖 id/version/name/author/description/tags/skinApiVersion/preview；fileRef 依赖 client/index.js、styles/theme.css、theme/*.json、preview/*。

18. **Runtime 消费哪些字段？**
    API 投影 files.bundle/styles/themeLight/themeDark/previewLight/previewDark；client bundle 必须自注册 `window.__ModuleLoader__.load({id:'dsh-skin/<id>', factory})` 且导出 apply；CSS 作用域 `body[data-dsh-skin="<id>"]`；theme JSON 的 --dsw-alias-* token 键。

19. **哪些 v1.2 provenance 应保留？**
    全部保留在 **generation 工作区**（design-spec.json 含 provenance、provenance.json、validation.json、evidence.json）。Package 保持最小：**不新增 provenance.json 进包**（非 Package Contract 必需文件，§14 原则），provenance 摘要（imageKey/provider/model/analysisVersion/generatorVersion）进新工件 build-manifest.json（工作区）。

20. **哪些中间证据必须留在 generation workspace 而不能进入 Package？**
    vision-raw.json、evidence.json、colors.json、provenance.json、validation.json、cache-log.json、queue-log.json、downscale-log.json、design-prompt.txt、design-raw.txt、repair-prompt-*.txt、preview.html、screenshot.png、fidelity.json、report.json——全部只进工作区。

## 二、真实构建图（v1.3 目标形态）

```text
SkinDesignSpec ──┐
BuildConfig ─────┼──▶ buildSkinPackage（纯函数；工作区内 tmp→rename 原子落位）
Naming ──────────┘        ├── manifest.json（version←config；preview←模板常量）
                          ├── theme/{light,dark}.json（ROLE_TOKEN 映射）
                          ├── styles/theme.css（css-render）
                          ├── client/index.js（模板）
                          ├── preview/{light,dark}.svg（模板）
                          └── assets/*（config.assets 逐字节复制，可选）
                                   │
                                   ▼
                    validateBuiltPackage（单一产物校验器：manifest/结构/CSS/client/preview/兼容/安全/绝对路径）
                                   │
                                   ▼
                    sealPackage（hashPackage → integrity.json，排除自身）
                                   │
                                   ▼
                    repository.install（Phase 3 已验证管线：stage→二次校验→atomic→registry）
                                   │
                                   ▼
                    Runtime（try-on/apply/restore：既有冻结面，零改动）
```

## 三、v1.3 决策清单（依据本审计）

- D1 新建 src/generator/package-build.ts：BuildConfig + buildSkinPackage + validateBuiltPackage + sealPackage + 绝对路径扫描；codegen.writeSkinPackage 保留为薄封装（既有测试/调用不破坏）。
- D2 BuildConfig 显式化：{packageVersion, generatorVersion, previewMode:'svg', assets?, evidence?}；不读 env/cwd/时间。packageVersion 缺省常量 '0.1.0'（稳定策略，用户可经 GenerateInput.version 覆盖——generate payload 细节本就未冻结）；generatorVersion=代码内常量（dsh-skin@1.3.0）。
- D3 Package 形状零变化：不新增 provenance.json / source / trust 字段（§3 冻结面 + §14）；trust 继续由 Repository 按 source 推导。
- D4 失败域拆分：新增 PACKAGE_BUILD / MANIFEST_BUILD / ASSET_BUILD / CSS_VALIDATION / PACKAGE_VALIDATION / INTEGRITY（保留 CODEGEN/CODEGEN_OUTPUT 兼容）。
- D5 确定性边界：Package 内容（manifest/theme/styles/client/preview/assets/integrity）= 字节级确定性对象；screenshot/zip=工作区/导出层产物，不在 v1.3 确定性对象内（边界文档化）。
- D6 integrity 沿用既有语义（hashPackage 排除 integrity.json 自身），不创造第二套 checksum。
- D7 v1.2 deferred 三项（vision_ground agent seam / 旧样本 interpretation / initialSpec provenance）不在 v1.3 范围内处理。
