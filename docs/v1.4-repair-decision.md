# RepairDecision：结构化修复决策契约（v1.4）

> 定位：DeepSeek 在修复轮输出的唯一机器面。Diagnosis = Evidence；RepairDecision = 设计决策（与 v1.2 分层一致）。
> 实现：src/generator/repair.ts（validateRepairDecision / applySpecPatch）。

## Schema

```json
{
  "targetRegions": ["cell-3-5"],          // 最差区域 id 集（或 ["global"]，用于全局指标问题）
  "problemAssessment": "…",               // 问题判断（自然语言，必填非空）
  "specChanges": [                         // ≤ maxChangedFieldsPerIteration（默认 4）
    {
      "path": "colorPalette[0].hex",       // 设计字段白名单路径
      "newValue": "#203a55",               // 新值（类型/值域按字段校验）
      "reason": "…",                       // 必填非空
      "targetRegion": "cell-3-5",          // 必填：targetRegions 之一或 global
      "expectedEffect": "…"                // 必填非空：说明期望改善哪个指标/区域
    }
  ],
  "confidence": 0.7                        // 可选 0..1；仅辅助信号，不参与自动接受
}
```

## 可写路径白名单（全部为 SkinDesignSpec 设计字段）

- colorPalette[i].hex（#RRGGBB）/ colorPalette[i].role（枚举）/ colorPalette[i].share（0..1）
- typography.family / typography.mono（fontFamilyIssues 校验）
- spacing.density（compact|comfortable|spacious）/ spacing.radius（0..32 数字）
- shapeLanguage / borderStyle / shadowStyle / backgroundStyle / headerStyle / sidebarStyle /
  messageStyle / inputStyle / buttonStyle / cardStyle / iconStyle（cssFragmentIssues 校验；空串合法=无样式）
- customCss（cssFragmentIssues allowRules）
- visualStyle（非空字符串）
- chromeElements / decorativeElements / assetCandidates（字符串数组元素）

## 受保护路径（一律拒绝）

provenance（编排层产物）、任何非白名单字段（skinApiVersion/package 身份/仓库元数据/运行时契约/source/trust/integrity 本来就不在 Spec 内）、
`__proto__` / `constructor` / `prototype` 段、含引号/空格/越界索引的路径、旧值覆盖型 payload（patch 只允许 newValue）。

## 校验规则（validateRepairDecision）

1. targetRegions 非空数组；每项 = 传入 worstRegions 的 id 或 "global"。
2. problemAssessment 非空。
3. specChanges 非空且 ≤ maxChangedFieldsPerIteration（默认 4；超出=整条拒绝，不静默截断）。
4. 每条：path 在白名单；newValue 类型/值域正确；reason/expectedEffect 非空；targetRegion ∈ targetRegions 或 "global"。
5. 拒绝脚本/文件系统/网络形态：newValue 只允许标量或字符串数组，禁止对象/函数；CSS 字段经 css-strings 层校验。

失败语义：非法决策 → REPAIR_DECISION 失败域；同迭代内最多重问 1 次（maxRepairAttempts=2，调用与结果落盘）；仍非法 → 安全停止，上一轮 Spec/Package 保持。

## 应用语义（applySpecPatch）

- 深拷贝 spec；按 path 顺序应用 newValue（旧值进 spec-patch.json 的 oldValue）。
- 应用后 validateSkinDesignSpec 必须通过（SPEC_VALIDATION）；失败 → 该轮 FAILED，Spec 不变。
- 振荡检测：patch 后 spec 的 sha256 出现在 seenSpecHashes → OSCILLATION 停止。
- 追踪链：RepairDecision.targetRegions → WorstRegion.id → fidelity metric → RegionEvidence → specChanges.path（repair-decision.json / spec-patch.json / metric-delta.json 全落盘）。
